# Индекс и история

SQLite хранит строки и fingerprints файлов, индексы идентичности/source и проекцию metadata. Это пересоздаваемый кэш; NDJSON и отдельные JSON/JSONL metadata остаются источниками данных. Обновление одного файла выполняется в транзакции; параметры повторно используются по [рекомендациям Microsoft](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/bulk-insert). Провайдер [Microsoft.Data.Sqlite 8.0.30](https://www.nuget.org/packages/Microsoft.Data.Sqlite/8.0.30) включён в сборку.

Текущий поиск сохраняет точные правила Unicode, Regex и literal substring через потоковое чтение строк из SQLite; substring/Regex не обещают индексный поиск. Незагруженные документы не становятся открытыми вкладками. Правки в памяти имеют приоритет над кэшем. Индекс проверяет SHA-256, пересоздание сохраняет старую БД, metadata и игровые файлы не удаляются.

История последних 2000 операций отображается из edit-history.jsonl соответствующего проекта. Старые записи без source hash читаются, но автоматическое восстановление для них запрещено. Новые записи восстанавливаются только при уникальной идентичности, неизменном source и совпадении текущего значения «После».
